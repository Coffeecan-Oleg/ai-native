# Встройка Битрикс24 и общие знания

Подготовлено 03.11.2026. Изменения проверены на локальной копии; в рабочем Gateway не применены.

## Встроенный запуск

Проверенный POST запуска возвращает первый корпоративный экран с HTTP 200, без перенаправления на `/admin`. URL запуска с `DOMAIN` и `APP_SID` остаётся на месте для инициализации официального JS SDK. В HTML нет токенов Битрикс24 или JWT Gateway. Сессия передаётся только cookie `Secure; HttpOnly; SameSite=None; Partitioned`.

Клиентский файл загружается со своего Gateway. Он подключает официальный `https://api.bitrix24.tech/api/v1/`, вызывает `BX24.init` и `BX24.fitWindow`, проверяет `/auth/bitrix24/frame-session`. REST-методы и `BX24.getAuth` не используются. Ожидание SDK ограничено 10 секундами, проверка cookie — 7 секундами. При сбое показывается понятное сообщение. Новый служебный GET возвращает только `{"ok":true|false}`, не раскрывает личность и не выдаёт токены.

На живом сервере подтверждён успешный POST с ответом 303 и отсутствие следующего GET панели. Точная причина остановки браузера/прокси пока не установлена. Подготовленный вариант исключает этот переход и добавляет штатную инициализацию SDK. Его работа в реальном портале должна быть принята после согласованного применения.

## Только общие знания

Корпоративные четыре инструмента `gateway_knowledge_space_list`, `gateway_knowledge_space_get`, `gateway_knowledge_document_get`, `gateway_knowledge_search` используют отдельное право `knowledge:read`. `memory:read`, `memory:write` и `memory:admin` не добавляются.

Новый reader читает только пространство `space:organizational-awareness` и точные пути из серверного профиля. Поиск ограничивается разрешёнными файлами до ранжирования и лимита. Личные пространства, соседние группы, неразрешённые документы, списки участников и запись недоступны. Индексы и файлы знаний не создаются; штатный журнал вызовов может обновляться. Старый не-корпоративный режим сохраняет прежний контракт `memory:read`.

Содержание существующей карты знаний этим пакетом не обновляется. Наличие доступа к файлу не означает актуальности его учебного текста. База знаний 2.0 Битрикс24 автоматически не синхронизируется с vault.

## OAuth и совместимость

В runtime нужно добавить `knowledge:read` в `GATEWAY_SUPPORTED_SCOPES` и `GATEWAY_MCP_OAUTH_SCOPES`; точная дельта без секретов входит в `runtime-env-delta.json`. Список инструментов, права владельца, срок токенов и доступ UniSender не расширяются.

Для существующего MCP-подключения требуется новый личный OAuth-вход: обычный refresh сохраняет прежний потолок. При фиксированном списке запрашиваемых прав клиенту также нужно добавить `knowledge:read`. В проверенном локальном плагине Codex 0.6.0 список scopes не задан, поэтому обновление его файлов не требуется. Старый токен получает `knowledge_scope_required` с `reauthentication_required=true`; личная память ради совместимости не включается.

## Проверка и откат

Выполнены локальные HTTP/MCP, unit и JavaScript-проверки. Отдельный браузерный стенд использует вымышленного сотрудника и имитацию родительского окна/SDK: это проверка отображения и cookie, а не приёмка реального Bitrix SDK.

Итог локальной регрессии: 131 проверка прошла; одна проверка создания symlink пропущена из-за ограничений Windows. Ещё пять сценариев клиентского JS прошли. Новый Docker-образ пока не собирался и на Linux не запускался: это часть будущего согласованного применения.

До изменения сервера нужны закрытая резервная копия БД/config/volumes, проверка исходного image digest и хешей файлов, сборка overlay только из согласованного пакета. После запуска — health, новая вкладка приложения, журнал входа, новый OAuth и четыре чтения знаний; запреты записи проверены локально. Откат возвращает прежний image/config. Новых миграций нет; существующие данные и ключ шифрования не удаляются.
