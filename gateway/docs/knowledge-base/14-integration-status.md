# Состояние интеграций — экран администратора в dev

В меню администратора: **Интеграции**. Адрес внутри Платформы:
`/admin/integrations/status`. Выпуск устанавливается сначала только в dev;
наличие инструкции не означает обновление production или готовность личного входа dev.

## Что показано

Экран строит снимок по зарегистрированным внешним маршрутам и служебным таблицам.
В текущем корпоративном каталоге это две операции чтения UniSender. Учебные
маршруты, отсутствующие адаптеры и произвольные записи БД в список не добавляются.
Наличие маршрута не подтверждает наличие ключа, доступ сотрудника или связь с API.
Выключенный настройкой маршрут UniSender явно помечается.

- Настроенные [лимиты частоты](12-external-service-limits.md): сотрудник/общие,
  доступная общая короткая серия и ожидание. Личная квота проверяется при вызове.
- [Защита сбоев](13-external-service-safety.md): занятые общие места,
  пауза после HTTP429 и отдельная пауза после сетевых сбоев/5xx.
- После истечения паузы: «Ожидает проверочный запрос» или «Выполняется проверочный
  запрос». Обновление страницы не делает такой запрос и не снимает паузу.
- Количество событий Gateway за24часа, последний успешный вызов в этом периоде
  и последняя причина отказа/ошибки с безопасной ссылкой по ID в журнал.

Время снимка и событий показано в UTC. Страница не обновляется автоматически;
кнопка «Обновить состояние» получает новый снимок. Сроки ожидания могут сократиться,
если выполняющийся вызов завершится раньше срока служебного места.

## Как читать статус

«Готова к допуску» относится к защите, а не к проверке работоспособности сервиса.
Последний успешный вызов Gateway — запись журнала, не текущая проверка API.
Если за период обращений нет, показано отсутствие наблюдений, а не «сервис работает».
Качество данных сервиса этим экраном не измеряется. Новый блок
[длительности обработки Gateway](17-integration-timings.md) добавляется отдельным
выпуском в dev; его наличие в исходниках не означает обновление рабочего сервера.

Данные страницы читаются из PostgreSQL в согласованной read-only транзакции
с ограничением времени запросов. При ошибке чтения возвращается503 и надпись
«Доступность сервисов неизвестна». Ошибочные данные не заменяются нулями.
Обновление страницы не читает ключ UniSender, не делает бизнес-вызовов, не изменяет
лимиты, счётчики, паузы и настройки. Обычная проверка корпоративной учётной записи
и обновление её сессии через Битрикс24 сохраняются.

## Что делать при отказе

1. Найти причину и время ожидания на карточке.
2. Не запускать автоматические повторы и не обходить ограничения другим приложением.
3. По ID открыть событие журнала и сопоставить с ответом ассистента.
4. Если состояние неизвестно, позже обновить страницу; администратору передать
   безопасный код и ID запроса. Ключи и содержимое бизнес-запросов не нужны.

Нет кнопок сброса защиты, отправки проверочного запроса или изменения конфигурации.
Просмотр требует действующего административного допуска, который проверяется
заново на сервере. Наличие старого scope в токене само по себе доступа не даёт.
Обычным сотрудникам общая статистика и этот пункт меню не открываются.
На странице нет токенов, параметров запросов, имён пользователей, полных payload
или произвольных текстов ошибок; показываются только разрешённые коды и подписи.

## Проверка выпуска

Синтетическая копия проверяет обе паузы, полную ёмкость, истёкшие места, ожидание
пробы, отсутствие истории, период24часа, отказ отозванному администратору,
read-only SQL и неизменность всех таблиц послеGET. Проверяются HTTP403/503/405,
экранирование и вывод неизвестной ошибки без её текста. Отдельно выполняется
просмотр настоящего HTML-ответа маршрута с вымышленными данными в браузере.
Новая миграция, секреты и права для этого экрана не требуются.
