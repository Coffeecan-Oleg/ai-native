# Место для образа и выпуска: проверка квоты

Статус: подготовлено для инструментов разработки. Наличие этого файла в Git не
означает установку нового инструмента в dev или обновление production. Статья
предназначена разработчику и администратору, обычному сотруднику команды не нужны.

## Почему недостаточно посмотреть свободное место

На последнем выпуске dev файловая система показывала свободное место, но импорт
Docker-образа остановился из-за отдельной Btrfs-квоты песочницы. Образ передался
целиком, что подтвердилось SHA256. Свободное место всей файловой системы и остаток
квоты отдельного подтома — разные величины.

Новая проверка читает файловую систему именно по целевому каталогу. На Btrfs UUID
и ID подтома определяются через read-only ioctl, затем читается соответствующая
группа квоты в `/sys/fs/btrfs`. ID 269 и UUID прежней песочницы в код не зашиты.
Проверяется состояние учёта; учитываются ограничения referenced/exclusive и
резервы данных и метаданных. Доступное место — меньшее из остатка квоты и
доступного места файловой системы. Чужие группы уровня 0 не ограничивают расчёт.

## Проверка перед импортом

После установки согласованной версии инструментов, из проверенного каталога:

```text
python workflow.py storage-check --archive image.tar.gz --report delivery.json --ssh-config SSH_CONFIG
```

1. Команда локально проверяет размер, SHA256, единственный тег, Git-коммит,
   config digest и UID образа, как `verify-delivery`.
2. Без извлечения файлов рассчитывается размер распакованного архива. Для
   прямого потока импорта берётся оценка двух полных распакованных копий плюс
   64 МиБ на служебные данные Docker. Повторное использование существующих слоёв
   не вычитается: такая оценка может отказать с запасом.
3. Только на `aiport` выполняется фиксированная команда чтения. К оценке на
   сервере добавляется запас 128 МиБ, уменьшить его аргументом нельзя.
4. `status=sufficient` и код завершения 0 означают, что проверка прошла в этот
   момент. `insufficient` означает нехватку места; `unknown` — невозможность
   подтвердить остаток. Оба случая возвращают ненулевой код.

Архив, SSH-ключ и реквизиты приложения на сервер этой командой не загружаются.
`docker load`, запуск контейнера, миграции, `apply`, очистка, `sync` и изменение
квоты не выполняются. Импорт остаётся отдельным согласованным действием. Прямой
ручной `docker load` не становится защищённым из-за наличия этой команды: проверку
нужно включать в разрешённый процесс загрузки.

Пример: расчёту требуется 800 МиБ, обязательный запас — ещё 128 МиБ. Если `df`
показывает 12 ГиБ, но после резервов квоты доступно 650 МиБ, результат будет
`insufficient`. Загрузка не должна начинаться. Нельзя обходить отказ другой
командой или удалять предыдущие рабочие образы без отдельного решения.

## Проверка перед окном выпуска

Контроллер повторяет проверку каталогов приложения и снимков при `plan`, `apply`
и перед началом worker. Сохраняется прежний минимальный бюджет из конфигурации,
в dev 512 МиБ; к нему добавлен запас 128 МиБ. Живые счётчики не входят в хеш
плана: изменение нескольких байтов не делает согласованный план другим, но
нехватка места блокирует каждую новую попытку.

Если квота закончилась уже после `apply`, но до окна, worker записывает состояние
`aborted` с безопасным кодом причины. Вход и Gateway ещё не менялись, миграций и
нового снимка не было. После устранения причины нужен новый план. Ошибки после
начала окна по-прежнему обрабатываются прежним сценарием закрытого восстановления;
возврат старой БД после допуска записей этим пакетом не разрешается.

Для первого создания dev прежний минимум 2 ГиБ также проверяется с учётом квоты
и обязательного запаса. Установленный dev заново не создаётся.

## Ограничения первой версии

- Поддерживается Linux x86_64/aarch64 с обычными согласованными плоскими Btrfs
  qgroups. При наличии групп уровня выше 0, неизвестном режиме, несогласованном
  учёте, неподдержанных флагах или недоступном sysfs результат — отказ, не «места
  достаточно». Иерархия и squota пока не поддерживаются.
- Для ext4/XFS без обнаруженных параметров квот возвращается проверка только
  файловой системы с явной отметкой. При параметрах квот либо неизвестной файловой
  системе проверка отказывает. Это не универсальная проверка квот всех хостингов.
- Снимок доступного места не резервирует блоки. Параллельные записи, метаданные,
  inode и особенности хранилища могут вызвать отказ позже. Оценка импорта не
  является гарантией. Размер рабочего дампа контроллер отдельно не прогнозирует.
- Ограничения памяти, проверки подписей, SHA256, сроки ожидания, секреты, права,
  схема БД и прикладные MCP-инструменты не меняются. Автоматического удаления
  образов, бэкапов, тестовых данных или пакетов нет.

Источники: [описание qgroups](https://btrfs.readthedocs.io/en/latest/btrfs-qgroup.html),
[Linux UAPI Btrfs](https://github.com/torvalds/linux/blob/v6.8/include/uapi/linux/btrfs.h),
[счётчики sysfs в Linux](https://github.com/torvalds/linux/blob/v6.8/fs/btrfs/sysfs.c).
