# Устранение лишних соединений при проверке прав

Изменение подготовлено и проверяется на копии. Наличие этой инструкции
не означает публикацию, приёмку нового Docker-образа или обновление dev/production.

## Причина задержки

В коротком синтетическом прогоне серии из20одновременных MCP-запросов
открывались321соединение PostgreSQL. Повторные проверки прав и отзыва токена
нужны, но каждый раз создавать для них новое соединение дорого.
Профилировщик считал только число вызовов и время функций, без SQL-параметров,
JWT, ключей и содержимого запросов. Вложенные времена не складывают в общее время.

## Что меняется

В корпоративном режиме два вида проверок используют одно отдельное
read-only соединение на процесс: действующие scope grants и отзыв Gateway JWT.
Остальные соединения и SQL-записи не меняются. Режим до корпоративного входа
сохраняет прежний путь. Новых пакетов, секретов, env, ролей и миграций нет.

**Разрешения и отзывы не кешируются.** Каждый вызов выполняет прежний SELECT
с прежними параметрами и условием срока/отзыва. Соединение работает с autocommit:
для каждой проверки получается новая транзакция и новый снимок БД.
В памяти помощника нет таблицы разрешённых пользователей или старого ответа.

Доступ к соединению сериализован: потоки не разделяют активную транзакцию.
Ожидание места ограничено2с, соединение —3с, SQL —2с, блокировка БД —1с.
У соединения включён default_transaction_read_only. Его максимальный возраст —60с;
следующее чтение после этого срока создаёт новое. Это срок соединения, не срок прав.
При смене DSN или закрытии соединения оно также заменяется.

Ошибка текущей проверки не повторяется автоматически и не заменяется старым
разрешением. Соединение отбрасывается, причина наружу передаётся безопасным кодом;
следующее обращение может открыть новое соединение. Если чтение прав недоступно,
доступ не разрешается. В дочернем процессе после fork создаются собственные
состояние, блокировка и соединение. Соединение родителя не используется и не закрывается.

## Как проверено на копии

Сравниваются одна базовая версия, одинаковые ресурсы и прежние пороги:
p95≤5с для коротких одновременных серий и≤2с при темпе до1чтения/с.
Обвязка меняет только источник вымышленных сотрудников и HTTP UniSender;
проверки подписей, прав, лимитов, пауз и аудита остаются настоящими.
Новый код подставляется только в одноразовую копию, с фиксацией хешей файлов.
Проверка исходного установленного образа отдельно подтверждает его неизменность.

Предварительный полный прогон: p95 серии10 —2,75с, серии20 —4,16с;
для серии20 новые соединения уменьшились до89, при прежних212вызовах проверки прав.
Все10сценариев защит завершены. Эти значения относятся к короткой синтетической
проверке на ограниченных ресурсах, а не к производительности рабочего сервера.
Финальный отчёт фиксируется отдельно; повторные прогоны не заменяют неуспешные результаты.

Целевые проверки с реальной одноразовой PostgreSQL:

- Новый запрет, его отзыв и истечение срока видны следующей проверке через то же соединение.
- Новый отзыв JWT запрещает проверку подписи/допуск; истёкший отзыв больше не действует.
- Два сотрудника при одновременных обращениях получают свои решения.
- Запись через соединение чтения отклоняется PostgreSQL.
- Недоступная БД и блокировка таблицы не возвращают прежнее разрешение.
- После fork дочерний процесс получает другой backendPID, родитель продолжает работу.

Отдельно проверяются возраст соединения, смена DSN, ограниченное ожидание,
очистка после ошибок и отсутствие повторного выполнения неуспешного запроса.
Полный набор исходных тестов и сквозные сценарии запускаются на отдельной БД.
Все лабораторные контейнеры, сеть, том и синтетические секреты удаляются.

## Выпуск и откат

После ревью требуется публикация точного пакета и штатный CI со сборкой
и приёмкой нового образа. Проверка подставленных исходников на копии не заменяет
эту приёмку. Затем — согласованный выпуск сначала в dev с обычной резервной копией,
проверками healthy, MCP без токена401, метрики404 и повтором нагрузки.
Миграции нет; возврат совместимого прежнего кода не требует восстановления БД.
Рабочий сервер и его интеграции этим пакетом автоматически не обновляются.

Обоснование жизненного цикла соединений и транзакций:
[конкурентный доступ Psycopg](https://www.psycopg.org/psycopg3/docs/advanced/async.html),
[autocommit и транзакции](https://www.psycopg.org/psycopg3/docs/basic/transactions.html).
