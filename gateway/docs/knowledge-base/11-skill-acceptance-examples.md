# Контрольные примеры навыка

Статус установки смотрите в статье о разработке; наличие этого файла в Git не подтверждает production-выпуск.

Платформа показывает контрольные задачи для ручной проверки ответа ассистента.
Файл не запускает модель, программу, рассылку или обращение к рабочему сервису.
Корректный формат примеров не означает, что навык прошёл проверку качества.

## Как подготовить

1. Возьмите `docs/examples/skill-acceptance/SKILL.md` и `test-cases.json` как образец.
   Там только вымышленные обращения поддержки. Ничьи рабочие навыки не изменяются.
2. В `test-cases.json` задайте от 3 до 5 задач. У каждой — уникальный ID, название,
   входные данные, ожидаемые факты и недопустимые действия. Используйте только
   вымышленные сведения без реальных имён, адресов, ключей и данных клиентов.
3. Укажите SHA256 точных байтов вашего `SKILL.md`. В PowerShell:
   `Get-FileHash -Algorithm SHA256 -LiteralPath .\SKILL.md`.
   Перенесите значение в нижнем регистре в `skill_sha256`. Перевод строки тоже меняет хеш.
4. Поместите оба файла в один ZIP и загрузите как новый черновик или новую редакцию.
   Лимит файла примеров — 16 КиБ; образец JSON показывает точные имена полей.

## Что увидит проверяющий

В карточке сохранённой редакции автор и владелец видят задачи и критерии. Черновики
не становятся общедоступными. Для них нет готового MCP-запроса: MCP выдаёт только
опубликованную редакцию. Не публикуйте черновик только ради проверки.

После обычной проверки владельцем и публикации в общей карточке появятся раскрываемые
примеры и готовый запрос. Скопируйте его в приложение с MCP Платформы. Ассистент должен
прочитать оба файла, сверить версию и SHA256, затем ответить только на вымышленный вход.
Если файлы отличаются, он должен остановиться. Реальные сервисы вызывать не требуется.

Сравните ответ с каждым ожидаемым фактом и списком запрещённых действий. Запишите
в своей задаче ID навыка и примера, версию, SHA256, приложение и замечания. Отсутствие
серверного вызова — непройденный шаг чтения. Событие completed не заменяет проверку качества.

Если инструкция изменилась, старые примеры помечаются устаревшими; запросы скрываются
до пересмотра примеров и обновления хеша. Неверный формат не даёт зелёной отметки.
Отсутствие примеров не блокирует существующий порядок публикации. Результаты ручной
приёмки этим MVP не сохраняются в отдельный реестр и не оцениваются автоматически.

Права, роли, scopes, секреты и существующие навыки этот выпуск не меняет.
