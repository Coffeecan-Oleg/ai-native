# Проверенный импорт образа в dev

Это инструмент разработчика для отдельного dev на kromin. Он добавляет принятый
образ в локальное хранилище Docker. Импорт не является установкой версии:
контейнеры, БД, маршруты, конфигурация и production не меняются. Статус установки
этой команды проверяйте по отчёту выпуска, а не по наличию файла в Git.

## Команда

Из проверенной копии инструментов:

```text
python workflow.py import-image --environment dev --archive image.tar.gz --report delivery.json --ssh-config SSH_CONFIG
```

Архив и delivery.json берутся из одного прошедшего проверки артефакта CI. Для
production эта команда отсутствует. Ключи Bitrix24 и UniSender ей не нужны.

## Что проверяется

На компьютере архив проверяется по SHA-256, размеру, тегу, commit и config digest,
UID 10001:10001 и декларации отсутствия корпоративных данных. Стабильная временная
копия проверяется ещё раз перед передачей. Вызов идёт только по фиксированному
SSH aiport и пути /opt/platforma-dev/code/image_import.py, без shell на ПК.

Предварительная оценка места учитывает gzip-файл, распаковку, две копии данных,
метаданные и резерв 128 МиБ. На сервере архив принимается в закрытый каталог,
повторно проверяется целиком, а место проверяется заново непосредственно перед
docker image load. Каталоги Docker manifest, OCI index и repositories не должны
содержать другие образы или теги. Нехватка и неизвестное состояние квоты блокируют
загрузку; квота не повышается, старые образы не удаляются.

Общая блокировка bootstrap и блокировка выпуска не допускают одновременного
управляемого релиза или второго импорта. Существующий тег с другим image ID
отклоняется. Тот же уже загруженный образ даёт already_present без повторного load.

## Результат и сбои

Успех: phase=accepted, verified=true, environment=dev, точные tag/image_id,
existing_runtime_unchanged=true. Флаг docker_load_performed показывает, была ли
действительно выполнена загрузка. Журнал сохраняется в закрытом каталоге
/opt/platforma-dev/state/image-imports/import-…/operation.json. Временный архив
после завершения удаляется; локальный исходный архив остаётся.

При потере соединения или таймауте результат может быть неизвестным. Автоматического
повтора, удаления образа или отката нет. На сервере остаётся маркер незавершённого
импорта; новые импорты и dev-выпуски блокируются до разбора. Администратор должен
сверить журнал, завершение процесса загрузки и фактический image ID. Простое
удаление маркера по инструкции из ответа ИИ не является безопасным восстановлением.

Образы не запускаются во время импорта. Прежние sudo и ручной docker load этим
инструментом не отзываются: защита обязательна в штатном процессе, а не является
новой системой разграничения прав. Чужие процессы могут занять место после проверки;
это оценка доступности, а не резерв ёмкости Docker.

После принятого импорта следует отдельный plan → apply → проверка → accept в dev.
Production требует своего согласованного выпуска.

Источник поведения загрузки: https://docs.docker.com/reference/cli/docker/image/load/
