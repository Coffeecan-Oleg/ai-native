# Ограниченная нагрузочная проверка dev

Это инженерный сценарий для отдельной одноразовой копии принятого образа.
Он не предназначен для рабочего адреса и не определяет предельное число сотрудников.
Существующий dev продолжает работать. Рабочие данные, ключи и production не используются.

## Что запускается

Три временных контейнера в отдельной Docker-сети `--internal`, без портов хоста:
Gateway384МиБ/1CPU, PostgreSQL192МиБ/0,5CPU и генератор запросов96МиБ/0,25CPU.
База `gateway_load_test` создаётся с нуля; после проверки её том удаляется.
Сценарий разрешён только на узле kromin, при наличии минимум800МиБ доступной
памяти и2ГиБ диска. При доступной памяти ниже160МиБ проверка останавливается.

Внутри копии заменены только источник личности и внешний HTTP UniSender:
20 вымышленных сотрудников, отдельные ключи подписания, частный HTTP-имитатор.
Настоящие JWT-проверки Gateway, корпоративные права, маршрутизация, PostgreSQL,
лимиты, паузы после ошибок и общий тайм-аут остаются в принятом образе.
Это не проверка личного OAuth, HTTPS внешнего провайдера и реальной корпоративной учётки.

## Сценарии и критерии

- Серии1/5/10/20 одновременных запросов разных сотрудников: только успешный ответ
  или контролируемый429; одновременно к провайдеру не более4; p95 не более5с.
- Пять одновременных запросов одного сотрудника: не более2 обращений к провайдеру.
- Десять чтений количества контактов с темпом до1в секунду: все успешны, p95≤2с.
- Три последовательных HTTP503 провайдера:502/502/502, затем локальный503
  без четвёртого обращения к провайдеру. Чтение локального профиля остаётся доступно.
- После штатной30-секундной паузы из пяти одновременных запросов допускается
  только одна проба; успешная проба восстанавливает работу.
- HTTP429 с Retry-After: общий отказ до конца паузы, затем восстановление.
- Медленный поток, который не нарушает15-секундный тайм-аут отдельного чтения:
  общий бюджет30с всё равно прерывает вызов с504; место освобождается,
  последующее чтение снова работает.
- Анонимный MCP получает401, операция отправки письма отклоняется без HTTP к провайдеру.

Между независимыми сценариями очищается только состояние защиты одноразовой БД.
Внутри сценария защиты не сбрасываются. Замеры p95 успешных и отклонённых
запросов сохраняются отдельно. Превышение бюджета задержки не отменяет остальные
сценарии, но общий результат остаётся отрицательным. Нарушение защит останавливает прогон.

## Запуск администратором

Из каталога gateway, с разрешённым SSH-доступом к dev:

```text
python release/load_lab/run.py --ssh-config <путь-к-config> --host aiport --image platforma-gateway:evening-<первые12SHA> --revision <полныйSHA> --output <новая-папка-результатов>
```

Образ должен быть заранее установлен и проверен. Скрипт не скачивает и не собирает
его, не выполняет deploy, не меняет постоянный dev. Новая папка сохраняет предыдущие
результаты. Для Windows передача двоичного архива выполняется Python, без конвейера
PowerShell5.1. Локальные проверки ограничителей: `python -m unittest discover -s release -p test_load_lab.py`.

## Как читать результат

В `load-receipt.json`: исходныйSHA, IDобраза, хеш обвязки, все сценарии, коды,
число HTTP-обращений, p50/p95/max, выборочные замеры памяти/CPU и подтверждение очистки.
`successful:false` нельзя переименовывать в успешную приёмку: сначала выясните причину.
Ошибка обвязки, нарушение защиты и превышение времени — разные основания.
Выборочный максимум памяти не является абсолютным пиком.

Проверяются неизменность старых контейнеров и контрольные суммы установленного
кода. Временные контейнеры, сеть, том БД и файлы синтетических секретов удаляются.
Приватная папка на сервере сохраняет только обвязку, очищенную диагностику и отчёт.
При обрыве SSH нельзя предполагать, что очистка завершилась: требуется чтение
статуса собственных ресурсов с меткой `platforma.load.lab`; чужие ресурсы не удаляют.

Эта проверка не заменяет длительную нагрузку, измерение production, реальные
клиенты сотрудников, восстановление из бэкапа и приёмку личного входа dev.
Конкретные результаты прогона публикуются в БЗ2.0 после фактического выполнения;
наличие этого исходника не означает, что проверка пройдена.
