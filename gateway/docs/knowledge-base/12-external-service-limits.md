# Частота обращений к внешним адаптерам

Статус установки смотрите в статье о разработке. Этот выпуск предназначен для dev;
production им не обновляется. Применяется новая добавочная миграция 0027.

## Что ограничивается

В корпоративном режиме (вход через Битрикс24) общий диспетчер внешних адаптеров
проверяет допуск перед вызовом. Сейчас из рабочих бизнес-интеграций подключён
UniSender: getLists и getContactCount. Один допуск относится к одному вызову адаптера,
а не к каждому HTTP-пакету внутри него. Все приложения одной учётной записи делят
одну квоту. Общая квота интеграции действует поверх личной.

По умолчанию на сотрудника и интеграцию: средняя скорость 30 вызовов в минуту,
короткая серия до 5. Для интеграции в целом: средняя скорость 120 в минуту,
серия до 10. Например, сотрудник может сделать пять вызовов сразу, далее допуск
восстанавливается примерно по одному за две секунды. Это сглаженная скорость
с допустимой серией, а не обещание ровно 30 запросов в каждом календарном окне.
Это внутренние настройки Платформы, а не объявленные лимиты поставщика.

Локальные навыки, знания, демонстрационные данные, очередь уведомлений, вход OAuth
и обновления сервера сюда не входят. Прямые запросы агента мимо Gateway этот
механизм не контролирует. Остальные бизнес-адаптеры общего диспетчера используют
тот же механизм при подключении; он не добавляет им маршруты или права.

## Что увидит ассистент

При превышении в JSON-результате gateway_call_tool будут ok=false, status=429,
error_code=EXTERNAL_RATE_LIMITED, retry_after_seconds и gateway_request_id.
upstream_contacted=false означает, что по этой попытке внешний сервис не вызывался.
Сессия MCP при этом может оставаться исправной: статус находится внутри результата
инструмента. Ассистент должен выдержать указанную паузу. Сервер сам не спит и не
делает повторный вызов. Переподключение сохраняет квоту учётной записи.

Если UniSender сам вернул HTTP 429, ответ имеет код EXTERNAL_UPSTREAM_RATE_LIMITED.
Первый ответ отмечает upstream_contacted=true. Платформа сохраняет общую паузу
интеграции, и последующие попытки блокируются локально. Числовой Retry-After
принимается в диапазоне 1–3600 секунд; неизвестный формат даёт паузу 60 секунд.
Содержимое ответа поставщика, сырой заголовок и ключ не возвращаются и не журналируются.
Для других адаптеров их собственная обработка ошибок сохраняется.

При недоступной БД, таймауте блокировки или неверной настройке возвращается
status=503, EXTERNAL_LIMITER_UNAVAILABLE и время ожидания 5 секунд. Новый исходящий
вызов не разрешается. Если ошибка возникла при сохранении паузы уже после ответа
поставщика, upstream_contacted=true честно отражает первую состоявшуюся попытку.

В журнале статусы ограничений помечаются «Частота ограничена»; идентификатор
gateway_request_id позволяет связать ответ и событие. Права просмотра журнала прежние.
Сохранённый повтор результата с тем же idempotency_key не расходует квоту.
Для новой операции допуск проверяется до потребления согласования. При ошибке
снятия заявки на выполнение ответ retryable=false требует проверки состояния,
а не автоматического повтора записи.

## Как администрировать

Состояние находится в PostgreSQL в отдельной таблице gateway_external_limits.
Транзакционная блокировка на интеграцию предотвращает превышение при параллельных
обращениях из разных процессов. Используется время БД. Перезапуск Gateway не сбрасывает
квоты. Вместо логина, почты или токена хранится SHA256 технического subject; это
псевдонимизация, не обещание анонимности. Таблица не выдаётся сотрудникам через MCP.

Применяются четыре необязательных параметра окружения:

| Параметр | Значение по умолчанию |
|---|---:|
| GATEWAY_EXTERNAL_LIMITS_USER_PER_MINUTE | 30 |
| GATEWAY_EXTERNAL_LIMITS_USER_BURST | 5 |
| GATEWAY_EXTERNAL_LIMITS_SHARED_PER_MINUTE | 120 |
| GATEWAY_EXTERNAL_LIMITS_SHARED_BURST | 10 |

Средняя скорость: от 1 до 6000, серия: от 1 до 60 и не больше скорости.
Некорректное значение не отключает защиту. Настройки меняются отдельным проверенным
изменением dev; этот выпуск использует значения по умолчанию без правок .env.
Параметры .env, роли, scopes и секреты production не меняются.

После допущенного вызова удаляется не более 100 полностью восстановленных личных
строк этой интеграции, неактивных свыше 7 дней. Общая строка не удаляется. Аудит,
сотрудники, навыки и другие таблицы этой очисткой не затрагиваются.

Для проверки использованы одноразовая PostgreSQL, параллельные процессы и имитация
ответов UniSender. Рабочие ключи и API для нагрузочной проверки не нужны.

Технические основания: [HTTP 429](https://www.rfc-editor.org/rfc/rfc6585.html#section-4),
[транзакционные блокировки PostgreSQL](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS).
