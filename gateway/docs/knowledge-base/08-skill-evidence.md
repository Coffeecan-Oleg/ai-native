# Как отличать чтение навыка от сообщения о его применении

Статус: функция входит в принятую основу a14c4f7; текущее состояние выпуска и границы приёмки указаны в [описании релиза](../release-1.0.md). Этот файл — исходник документации, а не доказательство публикации этой редакции в БЗ 2.0.

В каталоге есть ссылка «Мои чтения и запуски навыков»; в карточке — такая же ссылка с фильтром по ID. Раздел показывает только события вашей учётной записи за 30 дней; владельцу здесь также показаны только его события. Существующие административные разделы не заменяются.

После полного чтения SKILL.md через MCP сервер возвращает версию, SHA256 файла и manifest_sha256 всего набора. Если запись аудита сохранилась, read_receipt содержит recorded=true и непрозрачный id вида sr-… . Это подтверждает выдачу файла сервером этой учётной записи. Это не подтверждает, что модель выполнила все указания.

Если приложение поддерживает события started/completed/failed, оно может передать metadata_json с одним полем skill_read_id и тем же значением id. Поля skill_id, skill_pack и skill_version берутся из фактического ответа чтения; agent и client должны соответствовать реальному приложению и разрешённым меткам. Не подменяйте OpenCode/OpenClaw названиями Codex или Claude.

Связь принимается только для собственного чтения, точной версии и в течение 24 часов после чтения. Чужой ID, неверная версия или просроченный ID отклоняются. Позже история за 30 дней продолжает показывать уже сохранённую связь. После новой публикации событие может относиться к ранее прочитанной версии; это не даёт права заново читать архивный навык.

Форма метаданных для приложения (значение берётся из ответа, не из этого примера):

```json
{"skill_read_id":"sr_ЗАМЕНИТЬ_РЕАЛЬНЫМ_ID_ИЗ_ОТВЕТА"}
```

При recorded=false нельзя заявлять серверное подтверждение. Клиенты без поддержки связи продолжают отправлять события с пустыми метаданными: они показываются как сообщения клиента без подтверждённого чтения. Содержимое запросов, ответов, пароли и результаты работы в метаданные добавлять нельзя.

В таблице различаются «Сервер: прочитан SKILL.md», «Клиент: сообщил о начале», «…о завершении» и «…об ошибке». Даже подтверждённая связь completed с чтением не означает проверку качества результата. Для этого нужен человек или отдельная предметная проверка.
