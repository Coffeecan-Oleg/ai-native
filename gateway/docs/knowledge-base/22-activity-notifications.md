# Уведомления о действиях в Платформе

Статус: новая функция подготовлена для проверки. На основной сервер ещё не установлена.

После установки владелец откроет **Разделы → Уведомления**. В этом разделе можно включить или выключить отправку в служебный чат 68282 и выбрать нужные события. Настройки сохраняются кнопкой «Сохранить настройки».

Можно наблюдать входы сотрудников; загрузку, изменение и публикацию навыков; чтение файлов навыка через MCP; начало и результат применения навыка; добавление и изменение карточек агентов; изменения доступа и интеграций; прочие вызовы MCP; ошибки и отказы.

Пример сообщения на вымышленных данных:

> Платформа · действия сотрудников
>
> 10.11 16:30 · Иван Тестовый — загрузил навык: shared-example.
> 10.11 16:31 · Анна Примерова — опубликовал навык: shared-example.

Имя берётся из подтверждённого входа сотрудника. Если имя ещё неизвестно, будет показан его номер в Битрикс24. В сообщении есть постоянный ID объекта и ссылка на журнал. Для применения навыка отдельно указано, что это событие передало ИИ-приложение.

## Как не получить слишком много сообщений

Выберите только нужные категории и интервал: 30 секунд, 1, 5 или 15 минут. За один интервал отправляется не более четырёх событий одним сообщением. Остальные остаются в очереди. При большой активности очередь может расти; её размер виден на странице.

Общий выключатель останавливает новые уведомления. Уже ожидающие сообщения отменяются и не появятся после повторного включения. Начатая отправка может завершиться. То же правило действует для отключения отдельной категории. Старые записи журнала при первом включении не рассылаются.

## Что означает состояние доставки

- **Доставлено** — Битрикс24 вернул ID созданного сообщения. Это не означает, что коллега его прочитал.
- **В очереди** — событие ждёт своего интервала.
- **Доставка не подтверждена** — например, соединение оборвалось после отправки. Проверьте чат по коду отправки; автоматического повтора нет, чтобы не создать дубль.
- **Не доставлено** — сервис отклонил отправку или повторные отказы по лимиту не прекратились.
- **Отменено настройками** — владелец выключил канал или категорию.
- **Истёк срок ожидания** — событие ждало больше суток.

## Что нельзя определить по уведомлениям

Открытие файла навыка и применение — разные события. Применение видно, только когда ИИ-приложение передаёт начало, завершение или ошибку. Успешное завершение не оценивает качество ответа. Создание карточки агента не запускает автономный процесс. Действия, которые не проходят через Gateway и не записываются в его журнал, здесь не видны.

В сообщения не включаются тексты запросов и ответов, содержимое навыков, личная память, расход токенов и секреты. Получатели служебного чата будут видеть имена сотрудников и выбранные действия; при включении это нужно учитывать. Управлять настройками может только владелец Платформы. Обычный сотрудник и подключение ИИ через ограниченный OAuth не могут менять эту рассылку.

Это уведомления о действиях внутри работающего Gateway. Для сообщения о полной недоступности сервера нужен отдельный наблюдатель вне Gateway. Проверка доставки вебхука уже выполнена ранее; постоянная внешняя проверка пока ожидает сетевого доступа.

## Для администратора

Требуется миграция 0029: две новые таблицы настроек и очереди. По умолчанию рассылка выключена. Существующие роли, OAuth scopes, данные навыков и схемы их жизненного цикла не изменяются.

Настройки контейнера после согласования установки:

```text
GATEWAY_ACTIVITY_NOTIFICATIONS=true
GATEWAY_ACTIVITY_WEBHOOK_FILE=/run/secrets/platforma-activity-webhook
```

Вторая настройка — путь к файлу, а не секрет. Подключить отдельную защищённую копию уже согласованного вебхука только для чтения. Файл должен читаться сервисным UID/GID Gateway, быть обычным файлом, без прав записи группе и доступа остальным. Вебхук допускается только для akmetron.bitrix24.ru, адресат фиксирован — chat68282. Настройки других отправителей не меняются. Секрет не включается в Git, образ, формы, ошибки и журналы приложения.

Очередь ограничена 5000 ожидающими событиями. Переполнение подсчитывается, исходный аудит сохраняется. При работающем отправителе ожидание ограничено сутками, история доставки хранится 30 дней. При отказе БД/очереди аудит пытается сохранить исходное действие; диагностическое сообщение не содержит его данных. Параллельные процессы отправителя разделены блокировкой PostgreSQL.

Приёмка после установки: включить одну категорию, выполнить согласованное действие, сверить имя/ID/ID сообщения; выключить её и подтвердить отсутствие новых отправок; проверить отказ сотруднику; затем включить выбранный владельцем набор. До этого полная доставка нового контура не считается подтверждённой.

Откат: сначала выключить рассылку, затем вернуть прежний образ в согласованном окне. Миграция добавляет отдельные таблицы; их и новые записи не удалять. Восстановление старого дампа требует отдельного решения, поскольку теряет записи после снимка.

Отправка использует официальный метод [im.message.add](https://apidocs.bitrix24.ru/api-reference/chats/messages/im-message-add.html); успешный ответ содержит ID сообщения.
