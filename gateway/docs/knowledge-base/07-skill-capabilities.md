# Что навык действительно может сделать

Статус: подготовлено для следующего релиза. Навык — инструкция для ИИ-приложения; инструмент MCP — разрешённая функция сервера. Загрузка инструкции не добавляет инструмент и не запускает агента по расписанию.

В карточке появится блок «Что доступно с этим навыком». Для трёх редакций UniSender список операций проверен и привязан к SHA256 всех файлов. Если содержимое изменится, старый список перестанет считаться подходящим. Для других загрузок автор может добавить requirements.json по [примеру](../examples/colleague-check/requirements.json); это заявление автора, а не доказательство, что весь текст безопасен или полностью проверен.

Значения статусов:

- «Работа ассистента»: подготовка текста в приложении пользователя. Сервер не делает эту работу сам.
- «Маршрут разрешён»: маршрут есть в конфигурации и доступен текущему подключению. Доступ к конкретному списку и ответ UniSender ещё не проверены.
- «Не хватает права» / «Ограничение подключения»: текущему пользователю или токену не хватает разрешения. Повторный вход не заменяет выдачу прав.
- «Не подключено»: сервер не предоставляет заявленную операцию.
- «Список операций не указан/некорректен/устарел»: готовность не установлена. Это не зелёная отметка.

На текущем рабочем подключении UniSender предусмотрены только unisender.getLists и unisender.getContactCount. Они дают названия списков и количество контактов. Отправка, изменение данных, адреса получателей, рабочая статистика кампаний и данные CRM через этот адаптер недоступны. Право unisender:read необходимо для двух разрешённых операций; оно не выдаётся самим навыком.

Готовый запрос после установки релиза:

```text
Через MCP проверь gateway_corporate_skill_read(skill="shared-5e1b408fa3e94f828c7019b3c5e753f3", check_only=true). Покажи отдельно текстовые задачи, разрешённые маршруты, недостающие права и неподключённые операции. Не вызывай UniSender, не читай ключи и не считай эту проверку подтверждением связи с внешним сервисом. Если check_only пока отсутствует в схеме инструмента, обнови список инструментов; не выдумывай результат.
```

Проверка не выгружает содержимое навыка, не создаёт событие его чтения и не обращается к внешнему API. Обычное чтение SKILL.md тоже возвращает блок capabilities, поэтому старому клиенту не обязательно использовать новый параметр. Состав проверяется по декларации, а не путём исполнения произвольных инструкций из файла.

См. [полный сценарий проверки](06-skill-acceptance.md) и [доступ к UniSender](../unisender-readonly.md).
