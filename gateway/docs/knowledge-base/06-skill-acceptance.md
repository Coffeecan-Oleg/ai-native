# Как проверить свой навык: от загрузки до архива

Статус: функция входит в принятую основу a14c4f7; текущее состояние выпуска и границы приёмки указаны в [описании релиза](../release-1.0.md). Этот файл — исходник документации, а не доказательство публикации этой редакции в БЗ 2.0.

Понадобятся три участника: автор навыка, владелец Платформы и другой сотрудник. Один человек может быть автором и владельцем, но проверку чужого доступа выполняет отдельная учётная запись. Пароли друг другу не передают.

1. **Автор открывает Платформу** в [Битрикс24](https://akmetron.bitrix24.ru/marketplace/app/341/), затем «Каталог навыков» → «Загрузить навык». Выбирает готовый архив **colleague-check-1.0.0.zip**, приложенный к инструкции: распаковывать или создавать файлы самому не нужно. Внутри: [SKILL.md](../examples/colleague-check/SKILL.md) и [requirements.json](../examples/colleague-check/requirements.json). Название: «Проверка навыка — ИМЯ АВТОРА». В форме подтверждает допустимость общего доступа. Нажимает «Создать черновик». Ожидаемый результат: карточка черновика с постоянным ID вида shared-… . Скопируйте именно свой ID из карточки.
2. **Другой сотрудник** ищет этот ID в общем каталоге и просит свой ассистент прочитать его. Ожидаемый результат: черновик отсутствует и не читается через MCP. Владелец видит его в очереди проверки. Это проверка границ доступа, а не ошибка загрузки.
3. **Автор** открывает «Мои черновики и версии», карточку → «Отправить на проверку». Если нужны изменения, владелец возвращает материал автору. Ожидаемый результат отправки: статус «На проверке»; общая публикация ещё не появилась.
4. **Владелец** открывает очередь, читает все файлы, название, версию и список операций. Проверяет отсутствие секретов и опасных указаний. Подтверждает проверку и нажимает «Опубликовать». Ожидаемый результат: статус «Опубликован», версия 1.0.0, материал доступен коллегам. Публикация инструкции не создаёт новую интеграцию.
5. **Другой сотрудник** открывает карточку, затем отправляет своему подключённому ассистенту запрос ниже. Подставляет ID из шага 1. Ожидаемый результат: реальное чтение через MCP, версия 1.0.0, SHA256, карточка из трёх полей. В «Мои чтения и запуски навыков» появляется серверное чтение только у того, кто прочитал файл через MCP. Простое открытие карточки в браузере не считается MCP-чтением.

```text
Через MCP Платформы прочитай SKILL.md навыка ID_ИЗ_КАРТОЧКИ инструментом gateway_corporate_skill_read. Покажи skill_version, sha256, capabilities и read_receipt. Примени прочитанную инструкцию к вымышленному сообщению: «У сотрудника не открывается внутренний сайт; другие сайты открываются». Не обращайся к рабочим системам. Если MCP-инструмента нет, прямо скажи, что серверный вызов не выполнен.
```

Пример содержательного результата: «Проблема: внутренний сайт не открывается. Подтверждённый факт: другие сайты доступны. Следующий вопрос: открывается ли этот сайт у других сотрудников?» SHA256 и ID не копируются из примера: это значения ответа вашего сервера.

6. **Автор** открывает «Мои черновики и версии» → свой навык. В блоке **«Новая редакция»** указывает в поле «Версия в каталоге» значение **1.0.1**. В поле «Новый Markdown или ZIP, если меняются файлы» выбирает второй готовый архив **colleague-check-1.0.1.zip**, нажимает **«Сохранить черновик»**, затем **«Отправить на проверку владельцу»**. В нём уже добавлено четвёртое поле карточки: «Что пока неизвестно». Исходники второй редакции: [SKILL.md](../examples/colleague-check-v2/SKILL.md) и [requirements.json](../examples/colleague-check-v2/requirements.json). Другой сотрудник пока получает старую 1.0.0 с тремя полями. После повторной проверки владельцем и публикации тот же ID возвращает 1.0.1 с четырьмя полями. В «Истории версий» остаются обе редакции. Повторный запрос ассистенту должен читать файл заново, а не пересказывать прошлый ответ.
7. **Владелец** архивирует только этот проверочный навык. Он пропадает из общего каталога, новое чтение через MCP отклоняется. История остаётся доступна автору и владельцу. При восстановлении ранее опубликованный текст возвращается; более новый непроверенный кандидат остаётся черновиком. После проверки не архивируйте другие рабочие навыки.

В протокол запишите дату, приложение, свой ID навыка, версии, результаты шагов и идентификаторы запросов при наличии. Не включайте токены, реквизиты и текст чужих разговоров. Если ассистент только описал действие, но не вызвал MCP, шаг не пройден.

См. [что проверяет Платформа](07-skill-capabilities.md), [как читать учёт](08-skill-evidence.md).

Для публикации администратором: прикрепить к статье оба готовых ZIP из пакета; относительные ссылки на исходники и соседние статьи заменить ссылками БЗ. Сотруднику можно отправить действующую статью https://akmetron.bitrix24.ru/note/document/537/ с файлом для скачивания. Наличие исходника в Git не подтверждает обновление этой статьи; её редакцию проверяют отдельно. Итог фиксируется по [листу приёмки 1.0](../release-1.0-acceptance.md).
