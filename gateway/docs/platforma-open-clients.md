# OpenCode и OpenClaw в учебной Платформе

Статус этой инструкции: подготовленный пакет. Серверные контракты проверяются изолированно; конкретный Toolkit коллег ещё не идентифицирован. Это не заявление о пройденном тесте установленного OpenClaw.

## Сначала определить приложение

Название Toolkit может означать оболочку. Нужны название и версия движка, компьютер или сервер, один пользователь или общий бот. Достаточно сведений окна «О программе» и выводов `opencode --version` / `openclaw --version`, если команды доступны. Не присылайте файлы конфигурации, токены и OAuth-ссылки.

## Общие шаги

1. Откройте https://kromin.axion-test.akmetron.ru/join и войдите своим Яндекс-аккаунтом. Дождитесь одобрения Олега.
2. Добавьте личный MCP: https://kromin.axion-test.akmetron.ru/mcp. Не используйте общий токен владельца.
3. Примените подходящий пример из `addons/platforma-training/open-clients/`. Это фрагменты настроек: не заменяйте ими весь существующий файл. Сохраните остальные подключения и права приложения.
4. Примените CLIENT-INSTRUCTIONS.md в своём учебном проекте либо вставьте его текст как инструкцию этому ассистенту.
5. В чате попросите: «Проверь профиль доступа через MCP. Покажи наличие platforma:read, platforma:write, skills:read, telemetry:read и telemetry:write. Пока ничего не изменяй». Отсутствие права исправляется личным входом/учебным одобрением, а не подменой приложения.

## OpenCode

Выберите V1 или V2 по версии приложения: структура конфигурации различается. Готовы отдельные JSON-примеры. После добавления используйте `opencode mcp auth platforma`, затем `opencode mcp list`. Для повторного входа предусмотрен `opencode mcp logout platforma`, затем auth. Это очищает прежнюю авторизацию данного подключения; не выполняйте logout без необходимости. Вариант V2 фиксирует localhost callback и классический MCP handshake, чтобы не требовать от сервера более нового протокола или CIMD с переменным портом. Порт 19876 должен быть свободен на том компьютере, где запущен клиент.

Называйте приложение в событиях agent=opencode, client=opencode. Это не личный аккаунт и не замена OAuth.

Официальные форматы: [OpenCode V1](https://opencode.ai/docs/mcp-servers), [OpenCode V2](https://opencode.ai/v2/docs/mcp-servers).

## OpenClaw

Пример personal предназначен для личного экземпляра одного коллеги. Используются Streamable HTTP и OAuth. После настройки собственного экземпляра: `openclaw mcp login platforma`, затем `openclaw mcp status --verbose` и `openclaw mcp probe platforma --json`. Наличие записи в конфигурации ещё не подтверждает соединение: probe выполняет подключение.

Некоторые текущие команды настройки/входа OpenClaw требуют остановленного собственного OpenClaw Gateway; при его работе используйте поддерживаемые операции Control UI или запланированную остановку с владельцем этого экземпляра. Не останавливайте учебный Gateway Платформы и не выполняйте произвольный gateway stop из этой инструкции. Если `mcp` или указанных параметров нет, зафиксируйте версию — она может использовать другой адаптер, например mcporter. Не устанавливайте мост наугад.

Для общего бота применим только отдельный OAuth каждого участника. Шаблон shared намеренно выключен и содержит example.invalid: нужны настоящий HTTPS-адрес экземпляра OpenClaw, индивидуальные отправители и проверка разделения двух аккаунтов. Общий операторский токен не подходит. CLI login обслуживает операторские credentials; пользовательский вход per-requester запускается из обращения конкретного отправителя. Для такого режима потребуется отдельная приёмка установленного Toolkit.

В событиях используются agent=openclaw, client=openclaw.

Официальные сведения: [реестр и проверка соединения](https://docs.openclaw.ai/cli/mcp/registry), [транспорт и личная авторизация](https://docs.openclaw.ai/cli/mcp/transports).

## Учебная приёмка

Первый тест без изменений: профиль, контекст, пять вымышленных заявок и список навыков. Затем по явно согласованному заданию — новая заявка с собственной меткой LAB-XXXX, изменение приоритета и завершение на одном номере; после каждой операции — чтение карточки. Даты сверяйте со snapshot_as_of, а не с сегодняшним днём. Для шаблона получите существующий ID через MCP, не придумывайте его.

Пример запроса: «Прочитай переносимый навык создания учебных заявок и покажи план проверки с моей меткой LAB-XXXX. Укажи, какие поля изменятся. После моего подтверждения выполни путь создать → изменить → закрыть и проверь карточку. Учёт отправляй под настоящим названием моего приложения; покажи correlation_id и собственную статистику». Один успешный прогон даёт новые события started/completed. Не восстанавливайте старые события из отчёта задним числом.

Результат для Олега: название/версия Toolkit и движка; метка; ID заявки; версия/приоритет/статус; фактические agent/client; correlation_id; счётчики started/completed/failed. Никаких паролей, токенов и полных OAuth URL. Общие учебные изменения видны в /platforma/requests; агрегаты запусков владельцу — в /admin/telemetry/skills.

Негативная проверка: личная память владельца, чужая статистика и рабочие корпоративные системы должны оставаться закрытыми. После истечения access-токена клиент должен обновить его через refresh и повторно читать данные; старый refresh после ротации повторно не используется. Для общего Toolkit отдельно проверяется, что действия двух коллег не смешиваются под одной личностью.
