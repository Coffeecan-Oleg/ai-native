# Доставка библиотеки встроенной панели

Подтверждённая проблема на снимке пользователя: страница и фирменная оболочка
открылись, но обработчик script.onerror для внешнего BX24 SDK показал
«Не загрузился компонент связи с Битрикс24». Точная причина отказа внешнего
запроса (сеть, фильтрация или браузер) по этому событию не устанавливается.

Предложенное исправление: неизменённые байты официальной BX24.js v1 сохранены
в help_assets/bitrix24-sdk-v1.js. Источник, дата и SHA256 записаны в
bitrix-sdk-provenance.json. Версия API v1 не является уникальной версией файла,
поэтому точную редакцию определяет SHA256. Никаких загрузок или автоматических
обновлений SDK при запуске Gateway нет.

Фиксированный GET /auth/bitrix24/frame-sdk.js отдаёт только этот публичный
файл с application/javascript и nosniff. Маршрут выключается вместе с
GATEWAY_BITRIX_EMBED_ENABLED. Произвольные URL, проксирование и секреты
маршруту не нужны. Загрузчик использует адрес своего Gateway, script-src
сужен до self. Проверки сотрудника, приложения, источника запуска, cookie,
OAuth и все бизнес-права остаются прежними.

SDK получает стандартные сообщения среды Битрикс24 по своему официальному
протоколу. Наш загрузчик вызывает только BX24.init и fitWindow: REST через
SDK не используется. Ключи, токены и upstream-ответы в JS/HTML не добавлены.

Проверка на копии: полный HTTP factory Gateway, настоящий немодифицированный
SDK и две разные loopback host origins; личность, Bitrix parent и getInitData
имитированы. Реальный Bitrix API не вызывается. Старому загрузчику имитируется
отказ внешнего файла; новый загружает настоящий SDK со своего маршрута и
проходит handshake/session probe. Это не живая приёмка обновления портала:
после отдельного согласования нужен запуск внутри настоящего Битрикс24.

Обновление: получить SDK из официального источника, проверить разницу,
зафиксировать новые байты/хеш, выполнить тесты и показать пакет владельцу.
Откат: прежний Gateway image и конфигурация; БД этим изменением не меняется.
