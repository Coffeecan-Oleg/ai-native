# Актуальные инструкции корпоративной MCP Платформы

Целевая база: https://akmetron.bitrix24.ru/note/workspace/29/

Владелец поручил вести в этой базе пользовательскую документацию по мере развития корпоративного Gateway. Старые 20 учебных статей убраны в корзину 03.11.2026 по его прямому указанию. Они не являются актуальной инструкцией.

## Что добавлять

- Реально реализованные функции, относящиеся к основному порталу akmetron.bitrix24.ru.
- Для каждой функции: назначение, кому доступна, конкретные действия сотрудника, готовый запрос, ожидаемый результат, ограничения и способ проверки.
- Изменения входа, прав, адресов и поведения, которые затрагивают существующие инструкции.
- Разделять подготовленный код, установленную версию и проверку в действующем приложении. Инструкция не должна обещать неподтверждённый результат.

## Что исключать

Учебные практикумы, вымышленные заявки и сервисы, демонстрационные показатели, заглушки, планы как будто готовые функции, непроверенные интеграции, секреты, OAuth-коды и внутренние журналы с личными данными. Перенос полного чата в Битрикс24 не предусмотрен.

## Порядок при каждом изменении

1. Определить, изменилось ли поведение, важное сотруднику или администратору. Важные изменения эксплуатации, мониторинга, защиты и отката добавлять в администраторскую инструкцию: владелец отдельно напомнил 04.11.2026 пополнять БЗ 2.0 полезной информацией по разработке. Для мелкой внутренней правки без полезных новых действий отдельная статья не нужна.
2. Обновить соответствующий исходный текст в docs/knowledge-base. Если функции ещё нет в базе — подготовить небольшую отдельную статью.
3. Включить тексты и проверку фактов в отчёт выпуска; показать владельцу перед публикацией. Его согласование относится только к указанным статьям и версии.
4. После согласованного применения проверить функцию и опубликовать только актуальный текст. Не расширять права базы и не менять другие статьи без поручения.
5. Прочитать опубликованный текст, проверить ссылки и отображение. Сохранить в отчёт выпуска ID статьи, URL, версию исходника, дату проверки и результат.

Реестр публикаций: docs/knowledge-base/publications.json. Наличие локального исходника не означает публикацию. Автоматический периодический сборщик или публикация без согласования не включены.
