# Корпоративный режим без учебных заявок

Режим определяется GATEWAY_LOGIN_PROVIDER=bitrix24. Портал фиксирован на akmetron.bitrix24.ru, member_id закреплён на сервере.

## Поведение

- В корпоративном режиме не регистрируются веб-маршруты учебных заявок и формы /credentials. Пустой набор демонстрационных маршрутов в corporate_access запрещает их через MCP владельцу и сотрудникам. Серверный поиск возвращает только маршруты, разрешённые действующему аккаунту и его OAuth-подключению.
- Из базовых полномочий убраны platforma:read и platforma:write. Существующие корпоративные токены при проверке ограничиваются текущими правами. Широкие исторические scopes не возвращают доступ к демонстрационным операциям.
- Личный вход остаётся только через Битрикс24. Старый адрес /auth/yandex/login ведёт в корпоративный вход; callback Яндекса отклоняется; дополнительные service-login и disk-login возвращают 410. Сохранённые исторические реквизиты и данные не удаляются этим выпуском.
- Навигация содержит корпоративную справку, навыки, аудит и учёт навыков; владелец дополнительно видит сотрудников и состояние шлюза. Учебные одобрения не используются для корпоративного входа.
- Таблица «Сотрудники и входы» строится из минимальных данных bitrix24-login и успешных corporate_login/corporate_frame_login в аудите. Полный список сотрудников портала не загружается. Чужой портал, старая идентичность Яндекса, служебное закрепление приложения и неуспешные входы не образуют строку сотрудника.
- Разделяются первый вход, последний вход в панель, последняя успешная OAuth-авторизация MCP и последний успешный вызов инструмента MCP. Время отображается по Москве. Обновление сохранённых реквизитов не является входом; исторический неизвестный канал не восстанавливается догадкой. Обновление страницы с действующей сессией не создаёт новый вход.
- Это реестр наблюдавшихся входов, не кадровый справочник и не онлайн-присутствие. Историческая запись не доказывает, что сотрудник сейчас активен: текущий статус повторно проверяется в корпоративном доступе при обращении.
- Бизнес-данные, личная память, назначения, секреты и PostgreSQL не мигрируют и не удаляются. Исторические учебные записи остаются для аудита и отката, но недоступны в корпоративном интерфейсе и вызовах MCP.

## Проверка и откат

Проверки: синтетические тесты идентичности/OAuth/iframe, ограничения маршрутов и профиля, SQL с временными вымышленными таблицами и откатом транзакции, запуск полного локального HTTP-приложения. Живой результат фиксируется отдельно после согласования и применения.

Применение: образ поверх точного действующего digest, закрытая резервная копия конфигурации, дамп PostgreSQL и томов; меняется только Gateway. Откат — возврат прежнего образа и конфигурации, без восстановления БД. Точные хеши, команды и результаты — в отчёте выпуска.
