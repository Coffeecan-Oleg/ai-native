# Учебный обзор MCP для участников

При включённом onboarding одобренный участник входит через Яндекс и открывает `/admin`.
Это режим наблюдения: схема запроса, доступные учебные операции и ссылки на практику.
Владелец по тому же адресу сохраняет существующую общую панель.

Участнику доступны ровно три страницы только для чтения:

- `/admin` — устройство MCP и разрешённые серверным учебным профилем операции;
- `/admin/audit` — последние 50 событий только своего подтверждённого subject;
- `/admin/telemetry/skills` — только свой учёт навыков в `platforma-training`, при действующих правах учебного участника.

Фильтры actor_subject/project из URL не передаются в эти выборки. События других
пользователей, тексты запросов/ответов, сырые ошибки и токены не показываются.
Журнал выводит безопасное объяснение отказа OAuth allowlist. Библиотека навыков,
учебные заявки и памятка остаются доступны из навигации.

Новое право `access:admin` не выдаётся. Scopes, роли, grants, сроки, OAuth и
ограниченные MCP-токены не меняются. Даже старый браузерный cookie с группой admins
у одобренного участника открывает только персональные учебные страницы.
Каждое открытие повторно проверяет одобрение, связанные grants, срок и отзыв.
Делегированный MCP-токен не является браузерным входом.

Управление пользователями, интеграциями, секретами, общая статистика и личная память
владельца остаются закрытыми. Подмаршруты и экспорт не разрешаются по префиксу.
Все новые представления — GET, с no-store, CSP и экранированием метаданных.

Практика: открыть каталог навыков, попросить ассистента прочитать выбранный навык,
применить его к вымышленной задаче, затем сравнить свой журнал и события навыка.
Чтение файла не считается автоматически успешным запуском. События учёта должен
явно передать поддерживаемый клиент. Показатели не являются стоимостью или токенами.
Перечень разрешений на странице относится к серверному профилю, а ранее выданный
OAuth-токен приложения может оставаться уже. При соответствующем отказе нужен
новый личный вход; обновление refresh-токена не расширяет прежний список.

Применение: отдельное согласование конкретного пакета, закрытая проверенная копия,
обновление только Gateway. Нет миграций, изменений приватной конфигурации или
данных. Откат — предыдущий образ; данные и журналы не перезаписываются.
