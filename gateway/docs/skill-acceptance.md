# Приёмка корпоративного навыка

Проверяется полный путь: автор загружает Markdown/ZIP → сохраняет черновик →
отправляет владельцу → владелец проверяет конкретную редакцию и публикует →
ассистент читает SKILL.md через MCP → применяет инструкцию → сообщает итог.

Черновик не доступен общему каталогу и MCP. При работе над новой редакцией
сотрудники продолжают получать последнюю опубликованную версию. Архив скрывает
навык от новых чтений, сохраняя историю и возможность восстановления.

В ответе загруженного навыка `reviewed=true` и
`trust=user_uploaded_owner_reviewed` означают редакционную проверку владельцем.
Это не гарантия безопасности текста, качества ответа или разрешение выполнять
команды. Для старых непроверенных загрузок сохраняется `user_uploaded_unreviewed`.

«Учёт навыков» показывает разрешённое текущему пользователю название со ссылкой,
постоянный ID, версию, число запусков и завершений. Время отображается по Москве.
Для архивного, удалённого или недоступного материала сохраняется ID события.
При недоступном каталоге сами записи журнала остаются видимыми.

«Мои чтения и запуски» связывают событие клиента с серверной квитанцией чтения
конкретного SKILL.md. Статус завершения является сообщением клиента. Проверять
правильность результата нужно отдельно по исходным данным и контрольным примерам.

Для приёмки используйте вымышленные данные и один выделенный навык. Проверьте:

1. Отказ чтения нового черновика через MCP.
2. Публикацию владельцем и совпадение SHA256 прочитанного файла.
3. Начало и завершение с одной correlation_id и квитанцией чтения.
4. Фактический результат ассистента и появление событий в панели.
5. Новую редакцию, сохранение прежней публикации до проверки, историю версий.
6. Отказ чтения после архивирования и возврат после восстановления.

Не используйте администратора как доказательство доступности для обычного
сотрудника. Роли и отказы проверяются отдельно на изолированной базе, а вход
конкретного сотрудника — его собственным аккаунтом.
