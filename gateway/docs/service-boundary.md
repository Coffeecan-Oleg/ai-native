# Служебный доступ Gateway

`/metrics` по умолчанию отвечает 404. Статистика в административной панели,
`/healthz`, OAuth, MCP и встройка Битрикс24 от этого не меняются.

При установленном сборщике Prometheus администратор может отдельно включить
`GATEWAY_METRICS_ENABLED=true` и указать абсолютный путь
`GATEWAY_METRICS_TOKEN_FILE` внутри контейнера. Это отдельный случайный
служебный ключ, а не OAuth-токен сотрудника. Файл должен быть обычным файлом
с правами 0400/0600 на Linux, доступным только процессу сервиса, длина ключа
32–256 символов из A–Z, a–z, 0–9, `_`, `-`. Каталоги с файлом тоже закрытые;
монтирование только для чтения. Не помещать ключ в URL, Git, журналы или чат.

Сборщик посылает `Authorization: Bearer <ключ>`; неверный/отсутствующий ключ
даёт 401, недоступный/неправильный файл — 503 без деталей. Ответы no-store.
Заголовки X-Forwarded-For, cookie, query string и пользовательские роли не
заменяют служебный ключ. Для смены файла через bind mount контейнер нужно
пересоздать: атомарная замена файла на хосте не обновляет прежний inode.

В первом пакете сборщик и служебный ключ не создаются. Метрики отключаются,
так как действующий scrape-потребитель не подтверждён. Если он обнаружится,
включение оформляется отдельной проверенной настройкой с согласованием.

Сетевой bind 8000 меняется только после подтверждения пути существующего
прокси. SSH-адрес 10.53.13.2 не является фактическим адресом интерфейса
контейнеризованного стенда. Не закреплять динамический адрес 10.200.0.146.
