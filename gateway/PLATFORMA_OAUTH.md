# Ограниченный личный OAuth учебной Платформы

Плагин подключается через личный OAuth. Его токен сохраняет identity владельца для
аудита, но не административные группы и wildcard-права веб-сессии.

`docker-compose.platforma.yml` задаёт серверный предел:

- scopes: `skills:read`, `access:request`, `tools:read`, `tools:call`,
  `platforma:read`, `telemetry:write`;
- инструменты: профиль, поиск маршрутов, вызов маршрута и три технических события;
- бизнес-маршруты: только пять `platforma.*` из учебного каталога.

Запрашиваемые scopes пересекаются с правами пользователя и серверным пределом.
Если клиент не передал scope, применяется серверный предел. В JWT подписаны
`scope_ceiling` и `tool_allowlist`. При чтении JWT новые grants не расширяют предел;
административные группы удаляются. Refresh сохраняет прежние ограничения,
пересекает их с текущими правами пользователя и настройками сервера и может только
сузить выдачу. Удаление серверного профиля не расширяет уже ограниченный refresh.
Неполная конфигурация или wildcard в пределе приводят к отказу выдачи.

Scope `access:request` нужен инструменту профиля. Создание запросов доступа не
входит в allowlist и отклоняется сервером. `telemetry:write` разрешает три
согласованных технических события. Бизнес-запись не разрешена.

Строгая ресурсная политика остаётся включённой. Для чтения нужно отдельное
разрешение конкретному владельцу: system `platforma`, resource `*`, action `read`.
Для пилота разрешение выдаётся на 30 дней. Оно распространяется только на
вымышленные данные. Без него чтение
отклоняется. Разрешение администратора в веб-панели остаётся отдельным.
Ограниченный MCP-токен не принимается как браузерная сессия, в том числе через
Bearer или cookie: он не открывает веб-страницу credentials или админку.

Обычные веб-токены и установки без серверного OAuth-профиля сохраняют прежнее
поведение. Ранее выданные неограниченные токены нельзя считать ограниченными после
обновления: их нужно отозвать и выполнить новый вход. На этом учебном стенде вход
MCP до включения ограничений не завершался и такой токен не выдавался.

## Проверка на копии

Из `gateway/`, в отдельном окружении с установленными зависимостями Gateway:

```powershell
python -m unittest discover -s integration_tests -p test_oauth_limits.py -v
```

Этот набор использует настоящий JWT и MCP. Его запускают отдельно от `tests/`,
где существующие unit-тесты устанавливают dependency stubs. Проверяются PKCE,
подпись JWT, refresh, запрет повышения через grants, запрет admin HTTP/MCP,
запрет write-маршрута, явный resource-grant и сохранение identity.

После review владельца: резервная копия БД и приватных настроек, публикация своего
коммита, обновление только Gateway с Compose override, одно разрешение на чтение
учебного ресурса и новый OAuth-вход. Проверить отказ admin/write самим токеном,
чтение сервиса и связанной заявки, identity в аудите. При откате сохранить БД и
секреты; удалить только добавленное разрешение по его ID. Полный OAuth владельца
для отката подключения не использовать.
