# Справочник Платформы Акметрон

Справочник отвечает на вопросы по разрешённым документам и показывает название и путь к источнику. Для работы используется корпоративная Платформа в [Битрикс24](https://akmetron.bitrix24.ru/marketplace/app/341/). Адрес для MCP-клиентов — `https://platforma.akmetron.ru/mcp`.

## Запуск

Запускайте из каталога клиента на компьютере с браузером в Python-окружении с зависимостями Gateway. Команда проверяет доступность Платформы до входа:

```text
python guide.py --check
```

При `connection_ready=true` шлюз ответил, а `account_checked=false` означает, что личный вход ещё предстоит. Когда администратор назначит агенту отдельный профиль на сервере, войдите в браузере под этой учётной записью:

```text
python guide.py --subject "bitrix24:<member_id портала>:<ID агента>"
python guide.py --subject "bitrix24:<member_id портала>:<ID агента>" --find "Справочник"
```

Первая команда читает паспорт общих знаний и возвращает адрес подключения, портал и документ-источник. Вторая ищет фразу в доступных документах.

## Настройка первого агента

Используйте активную внутреннюю учётную запись, выделенную справочнику. Профиль сервера сопоставляет её полный идентификатор с `GATEWAY_KNOWLEDGE_GUIDE_SUBJECT`. Клиент проверяет личность, права `skills:read` и `knowledge:read` и точный набор методов: `gateway_access_profile`, `gateway_knowledge_search`, `gateway_knowledge_document_get`. Пилот использует существующий каталог и паспорт `awareness/project-profile.md`.

## Приёмка с администратором

Перед первым входом администратор закрепляет роль за выделенной учётной записью. Для проверки нужен существующий контрольный файл `acceptance/closed-control.md` в пространстве общих знаний. Его содержимое — строка `AKMETRON-GUIDE-CLOSED-CONTROL`. Администратор проверяет существование файла и оставляет его вне списка опубликованных документов. Используйте только эту вымышленную метку.

Выполните `python guide.py --subject <полный-ID> --acceptance`. Войдите в Битрикс24 под учётной записью справочника. Клиент прочитает паспорт, проверит поиск метки и запросит закрытый файл. Когда программа предложит сделать паузу, администратор выставляет персональный запрет `knowledge:read`, сохраняя роль назначенной. Нажмите Enter. Клиент повторит чтение паспорта в том же соединении и покажет три ID для сверки. После проверки администратор может снять именно этот персональный запрет и снова проверить обычное чтение паспорта.

В Битрикс24 владелец открывает «Автономные агенты», сохраняет карточку и выбирает источник «Справочник · чтение документов» с нужным ID пользователя. В карточке видны выдачи документов, отказы и ошибки. ID ответа совпадает с ID в журнале. Поиск без совпадений отображается в результате приёмки. Статус отражает выдачу документа шлюзом. Текст окончательного ответа виден в клиенте.
