# Серверный модуль контроля доступа

security_guard.py — проверяемое ядро политики на Python 3.9+ без внешних зависимостей. Оно дополнительно проверяет профиль сотрудника перед операцией. Само копирование файла не включает защиту. Авторизация, OAuth, хранение пользователей, ACL источников и работа сессий остаются ответственностью Gateway.

## Подключение к существующему Gateway
1. Определите работающие обработчики всех операций с документами, поиском, памятью, skills, CRM, почтой и репозиториями. Проверьте также прямые HTTP-маршруты, фоновые задания и альтернативные вызовы инструментов.
2. Загружайте актуальный профиль из закрытого административного хранилища. Сотрудник не может редактировать его или отчёт интеграции. Сверяйте реальную личность из сессии с subject, используйте серверную принадлежность ресурса проекту. Значения project, resource_kind, skill_impact, отправитель и approval из запроса не являются доказательством.
3. Вызывайте authorize перед любым чтением, записью или внешним действием. При отказе прерывайте операцию без побочных эффектов. Не давайте агенту инструмент для обхода проверки. Существующие ограничения Gateway и ACL источника также должны пройти: результат ядра не отменяет их.
4. Для списков и поиска фильтруйте данные на уровне запроса и проверяйте каждый результат до передачи агенту. Никогда не отдавайте общий результат для последующей фильтрации моделью. Память пользователя и проекта проверяйте отдельно. Общий scope memory:read не заменяет членство в проекте.
5. Для создания используйте точный ID разрешённого контейнера (рабочее пространство/папка/каталог новых skills), задавайте проект нового объекта на сервере. Проверяйте имя/путь и отсутствие существующего объекта атомарно. Предотвращайте path traversal, symlink escape, перезапись, замену ссылки и гонки. Запрет изменения существующих skills должен действовать для прямого Git/CRM/файлового маршрута тоже.
6. Для CRM определяйте влияние на skills по зависимостям, схеме и текущей версии. Неизвестное влияние запрещает изменение. Значение none допустимо только после серверной проверки. При affects_skills требуется одноразовое согласование владельца, привязанное к subject, проекту, ресурсу, операции и полному payload. approval_check должен атомарно проверить и использовать серверную запись согласования, включая её срок, отзыв и версию ресурса. Нельзя брать bool из запроса. Проверку версии и само изменение выполняйте в одной транзакции/с блокировкой.
7. Для почты проверяйте личность владельца OAuth и действительный From/Sender/alias до отправки. resource в ядре — проверенный ящик. Общие Google-credentials владельца сотруднику не передаются. Разрешение send не включает read.
8. При отзыве отключайте профиль и сессии, memberships и ACL источников. Проверяйте старый токен. Изменение status ядра прекращает только операции, проходящие через него, и не отменяет внешние ACL или скачанные копии. Не кешируйте профиль без инвалидации при отзыве.
9. Записывайте минимальный аудит: время, subject, project, resource ID, operation, allowed/reason, версия профиля. Без payload, текстов писем, паролей и токенов. Назначьте владельцу доступ к журналу и срок хранения по его условиям. Не называйте этот журнал SIEM.

## Проверки и активация
python -m unittest discover -s system -v

16 тестов проверяют ядро. Дополнительно обязательны реальные вызовы под личностью сотрудника, в том числе в обход обычного MCP-обработчика. Профиль example-profile.json остаётся draft, пока не заполнены реальные IDs и не проверена интеграция. Не помечайте систему active по результату unit-тестов.

Для Gateway на другом языке реализуйте эквивалентную проверку в его серверном стеке и перенесите эти тестовые сценарии. Не добавляйте отдельный Python-сервис с широкими полномочиями ради совместимости. Не запускайте недоступный backend автоматически.

## Область защиты
Это базовая система контроля доступа и согласования. В комплекте нет антивируса, DLP, SIEM, сканеров Cisco, Presidio или гарантий распознавания персональных данных. Локальный терминал сотрудника и его отдельные подключения контролируются средствами клиента/ОС. Чувствительные локальные папки не подключаются, пока такие ограничения не проверены. Инструкции в документах считаются данными, а права проверяются сервером независимо от ответа модели.
