# Приёмка рабочего процесса

Это контроль результата, а не разрешение применить изменения.

| Этап | Ожидаемый результат | Основание |
|---|---|---|
| Источник | Указаны commit, проверенный diff и image ID | Git + CI acceptance/delivery |
| Доставка | SHA256, размер, тег, commit и config digest совпали | workflow.py verify-delivery |
| Dev bootstrap | Отдельные project/DB/тома, новые ключи только на сервере | bootstrap receipt + реальные проверки |
| Сеть | Порт только loopback; по SSH-туннелю health=200 | inspect + HTTP |
| Авторизация | Без токена MCP=401; до dev-приложения вход явно pending | HTTP, без подмены реального OAuth |
| Сохранность | Перезапуск сохраняет dev-БД и ключи | sentinel/хеши на копии |
| Выпуск | Закрытие → снимок → миграция → проверка → awaiting_accept | журнал release |
| Допуск | Только accept открывает вход | HTTP 503/200 + статус |
| Границы | Dev-команда отвергает production project/DB | CLI отказ |
| Публичный dev | TLS, dev issuer, правильный маршрут | живая проверка после разовой настройки |
| Bitrix24 | Владелец вошёл лично, свежая сессия, каталог доступен | браузер/MCP, не healthy |
| Production | Штатный SSH release и совместимость валидаторов проверены | отдельная квитанция оператора |

Первые технические пункты проверяются на синтетической копии. Для последних трёх нужна
фактическая установка и отдельная приёмка. Публикация инструкции в БЗ 2.0 не означает их выполнения.
Актуальные статьи для сотрудников публикуются после приёмки соответствующей функции.
