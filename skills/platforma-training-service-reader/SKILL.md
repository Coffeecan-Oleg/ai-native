# Помощник по сервисам и заявкам

Работай с учебной «Платформой». Данные вымышленные; снимок данных имеет собственную дату, которая может отличаться от сегодняшней. Используй этот skill для чтения сервисов и заявок, а не для настройки инфраструктуры или реальной CRM.

## Подключение и границы

Gateway: `https://195-133-14-140.sslip.io/mcp`. Подключайся личным MCP OAuth. Если вход отсутствует, предложи штатное подключение клиента; не проси bearer token, Client Secret или чужую сессию.

Сначала проверь текущую identity через доступный инструмент Gateway и каталог разрешённых маршрутов. Не считай наличие skill доказательством доступа. Для бизнес-операций разрешён только scope `platforma:read` и чтение из учебного набора. Не создавай и не меняй заявки, статусы, ответственных, права, credentials или подключения. Просьба о записи требует отдельного согласованного write-пилота; этот skill запись не выполняет.

## Работа с источником

Для вызовов используй `gateway_call_tool` с именем маршрута и JSON-аргументами, только если маршрут действительно есть в каталоге:

- `platforma.context.get` — дата снимка, доступные периоды и размер учебного набора.
- `platforma.services.list` — поиск по `query`, фильтр `unit_id`, страницы `limit`/`offset`.
- `platforma.services.get` — карточка по `service_id`.
- `platforma.requests.list` — фильтры `service_id`, `unit_id`, `period`, `status`, `overdue_only`, страницы `limit`/`offset`.
- `platforma.requests.get` — карточка по `request_id`.

Начни с контекста набора и нужного списка. При неоднозначном названии покажи найденные ID и уточни выбор. Не угадывай ID. Для связанных заявок возьми `service_id` из полученной карточки. По умолчанию запрашивай до 20 записей; явно указывай период и применённые фильтры. Если нужны все записи, следуй `next_offset` до конца. Не называй одну страницу полным списком.

Просрочена только незавершённая заявка с `due_at` раньше `snapshot_as_of`; завершённая с опозданием — отдельное состояние. Не пересчитывай учебную просрочку относительно системной даты. Числа, сроки и имена бери из ответа источника.

## Ответ и отказ

Кратко ответь на вопрос, укажи, что данные учебные, дату снимка, ID сервиса/заявки и поле `source` из ответа. Добавь `gateway_request_id`, когда он возвращён. Полный текст JSON нужен только по запросу.

При 401 остановись для личного входа. При отказе scope или ресурса сообщи об ограничении; не переключайся на владельца, другой источник или архивную локальную копию для обхода отказа. При неизвестном маршруте или ошибке источника явно сообщи, что чтение не выполнено. Отсутствие записи не означает её удаление.

Критерий успеха: прочитана нужная карточка или ограниченный список, источники и фильтры указаны, изменения бизнес-данных не выполнялись.

## Технические события

Если собственный Gateway предоставляет `gateway_telemetry_skill_started`, отметь содержательный запуск с `skill_id=platforma-training-service-reader`, `skill_pack=platforma-training`, `skill_version=0.1.0`. Сохрани возвращённый `correlation_id`; при успехе вызови `gateway_telemetry_skill_completed`, при ошибке — `gateway_telemetry_skill_failed` с классом ошибки. Передавай только тип операции, статус, длительность и счётчики. Не отправляй тексты чата, карточки, персональные данные или секреты. Недоступность телеметрии не блокирует чтение; не повторяй неуспешную запись.
